# Group 4 evaluation and one consolidated in-game checklist

**All in-game findings: NOT YET VALIDATED.** The agent did not launch, control or automate BeamNG.drive. No screenshots or real driving results are claimed. This is the single manual checklist covering 4A, 4B and 4C.

## Automated evidence

The offline test suite exercises mapped directional counts, one-way reversal, left/right traffic, turn-lane parsing, estimated versus mapped widths, parking/sidewalk sides, all four backend combinations, real SUMO imports, restrictions, offset/multiway junctions, ramps, roundabouts, bridge separation, deterministic graphs, rebase-stable junction IDs, source updates/checksums, ambiguous matches, missing executables and timeouts. An end-to-end synthetic server test rebuilds grading, friction masks, terrain chunks, both mesh backends and the AI graph while leaving the Legacy anchor intact.

The shared Lua state tests exercise four consecutive switches, requested/accepted/loaded states, driving deferral, current terrain and applied-AI barriers, stale results, timeout, rollback and failed import. Stubbed core tests import the new terrain under the stationary hold at the same origin without moving the vehicle, reject invalid masks, restore prior terrain, and preserve the hold if restoration fails. Strict-import tests reject surface-less retries. These are offline assertions, not engine findings.

`docs/roadintel-benchmark.json` records seven repeats over T/cross/offset/multiway/ramp/roundabout/bridge fixtures plus left-hand cross/roundabout fixtures. It includes actual cold netconvert time, warm cache hits, tile/mesh export times, graph times, payload/output sizes and fresh 512² terrain rebuilds. Synthetic results do not predict real map-source latency or game frame times. Source preparation and policy: [ROADINTEL.md](ROADINTEL.md).

Final Windows verification covers **95 Python test modules: 1,364 passed tests and 35 skips**, combining the latest successful module logs and all seven simulated-drive cases across reruns. The final affected-code run passed **227 tests in 12 modules**, including **26 Group 4 tests**. All **61 Lua suites / 5,309 assertions** passed under Lupa 2.8 / LuaJIT 2.1. Details, skip reasons and log hashes are retained in [roadintel-verification.json](roadintel-verification.json). This is cumulative verification, not a claim that one full-suite invocation was entirely green.

The initial full run found two stale/platform fixtures and timed out at 1,500 seconds in the default 15-km drive module. A starting-commit baseline reproduced the Windows prune-path audit failure. The corrected simulated-drive matrix uses `BNGE_DRIVE_REBASE_M=2000` and `BNGE_DRIVE_SPEEDUP=1`: about 2.6 km with one rebase in each of four terrain/mesh configurations, plus three accelerated follow scenarios at 134/200/250 m/s with delayed terrain/anchors. All seven passed across reruns. The default 15-km route was **not completed**. Test harness corrections normalize file paths, end follow-event attribution when a rebase changes coordinate frames, and wait for test-server descendant log handles during Windows teardown. The simulated wall-frame timing is diagnostic and is not a game frame-time result.

These are tiny synthetic networks, not a regional-scale memory measurement. Additional topology/markings cost work: the roundabout's Legacy-geometry median increased from 28.60 to 44.84 ms, while GEOS increased from 154.47 to 172.47 ms. ## Manual checklist — every item pending user testing

- [ ] **Preparation — NOT YET VALIDATED:** Prepare complete full-tag OSM extracts and neighboring core caches for each route using the pinned environment and `prepare_roadintel.py`. Set `BNGE_ROADINTEL_DIR` in the server's environment and keep roads/surfaces enabled. Keep the extract SHA-256, generated pointers and Overture release. Confirm the settings show both selectors independently. Preserve the current working Group 1 installation as a rollback copy.
- [ ] **Fixed comparison setup — NOT YET VALIDATED:** Use the benchmark defaults: clear weather, 2026-09-22, 10:00 local mean solar time, identical vehicle/graphics/traffic amount, 70° FOV. Use the existing fixed ground view (1.7 m AGL, −3° pitch) and aerial view (250 m AGL, 600 m back, −18° pitch), with the place's saved heading. Record any unavoidable camera difference. Do not use a different weather/time or graphics preset for the SUMO capture.
- [ ] **Locations — NOT YET VALIDATED:** Begin at Fells Point **39.28188, −76.59114**, then Harbor Point **39.2801, −76.5890**. Also use the existing `amsterdam` urban benchmark **52.3702, 4.8840**, the existing `az_ut_line` US-163 highway benchmark **36.998218, −110.102293**, and the left-driving `tokyo_shibuya` benchmark **35.6595, 139.7005**. Keep existing place coordinates/cameras unchanged. Within each prepared region, choose mapped approaches/divided carriageways/ramps where the diagnostics confirm usable source data; record feature/junction IDs rather than applying place-specific fixes.
- [ ] **Four combinations and screenshots — NOT YET VALIDATED:** At each site capture `legacy-geometry_legacy-intel`, `geos-geometry_legacy-intel`, `legacy-geometry_sumo-intel`, and `geos-geometry_sumo-intel` from both saved camera views. Stop on supported terrain away from curbs, bridge decks and tunnel supports before each change. Wait for both status lines to report loaded, with no pending/incomplete phase. Save paired screenshots with the site, combination and camera in the filename.
- [ ] **4A layout — NOT YET VALIDATED:** Compare lane totals and directional split, one-way direction, driving width, lane/centerline offset, parking/shoulder space, sidewalks, divided-road medians and changes in lane count. Check that markings stay within the new pavement, the terrain-painted asphalt and tyre friction reach the same envelope, and bridge/tunnel elevations remain continuous. Separate mapped values from estimates/fallbacks using the per-feature diagnostics.
- [ ] **4B junctions — NOT YET VALIDATED:** Drive T and four-way junctions, offset and multiway intersections, ramp merges/splits, divided junctions, and circular/irregular roundabouts in both travel directions where legal. Check entry/exit alignment and priority. At a bridge/underpass, confirm that GPS and traffic cannot jump between levels. Record which junctions use SUMO and which fall back; a fallback is not evidence of a SUMO improvement.
- [ ] **4C markings and AI — NOT YET VALIDATED:** Inspect lane dividers, asymmetric centerlines, road edges, supported mapped arrows, stop lines and crossing alignment. Verify that arrows agree with allowed movements and local driving side. Spawn stock traffic and follow a GPS route through each junction for at least two minutes; note wrong-way cars, forbidden turns, lane changes, stuck queues, signal obedience and implausible paths. Do not interpret the retained SUMO lane mask as proof that BeamNG enforces it.
- [ ] **Terrain transaction — NOT YET VALIDATED:** While stopped, switch Legacy → SUMO → Legacy → SUMO, then change geometry independently and repeat. Confirm one hold/rebuild per transaction, new terrain/road/AI data, no old painted masks, overlapping meshes, stale navgraph, missing collision or retained pooled shape references. The car and camera should keep their position across the identity-origin rebuild. Reconnect and restart the server to check persistence and fresh model selection.
- [ ] **Deferral and recovery — NOT YET VALIDATED:** Request a switch while driving: it must stay pending until safely stopped. Repeat while supported by a bridge/curb/tunnel: it must defer. In multiplayer it must remain pending. With the car parked, disconnect the companion during a rebuild, or temporarily select an empty prepared-data directory before reconnecting. Confirm a visible rejection/incomplete state and released hold; choose Legacy explicitly and verify a complete acknowledged terrain/mesh/AI rollback. If the UI reports terrain restoration pending, it must retain the simulation hold until explicit recovery succeeds or you leave the mission. Late results must not import terrain or report success after a timeout. Do not delete cache files used by a running selection.
- [ ] **Streaming/performance — NOT YET VALIDATED:** Repeat the same urban route and highway route for each combination, first cold and then warm. Record tile-build median/p95, model-cache hit/miss counts, server fallback counts, frame-time median/p95/worst, streaming backlog/latency, rebase transitions and any vehicle collision discontinuity. Test increasing highway speeds within your chosen vehicle's capability. Keep traffic, cameras, route and cache state comparable. Real frame times are still pending; the offline report contains only server-side synthetic measurements.
- [ ] **Record acceptance — NOT YET VALIDATED:** Attach matched screenshots, settings/status snapshots, source/cache versions, feature and junction IDs, server logs and the route observations. Mark each location/checkpoint pass, fail or fallback only after driving it. Retain Legacy as the default until this comparison is accepted.
